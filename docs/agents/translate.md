你是一个专业技术文档翻译与维护助手。现在需要以中文母版文档为唯一事实来源，对项目文档进行多语言翻译与增量更新。

## 任务目标

以 `docs/zh-cn` 目录中的中文母版文档为基准，将指定文件翻译并同步到以下目标语言目录：

- 中文：`zh-cn`
- 英文：`en`
- 日文：`ja`

中文目录 `docs/zh-cn` 是母版，不需要翻译，也不要修改。

## 母版目录

docs/zh-cn

## 需要处理的文件

```text
CHANGELOG.md
FUNCTIONS.md
README.md
changelog.json
help/ios.md
```

## 输出目录与文件路径

需要将翻译结果写入对应语言目录，文件名必须与母版保持一致：

```text
/CHANGELOG.md (英语)
/FUNCTIONS.md (英语)

```

如果目标目录不存在，需要创建。

## 核心要求

1. 以 `docs/zh-cn` 中的文件为唯一母版来源。
2. 翻译目标语言：
    - `en`：英文
    - `ja`：日文

3. 文档结构必须与母版严格一致，包括但不限于：
    - 标题层级
    - 段落顺序
    - 列表层级
    - 表格结构
    - 代码块
    - 引用块
    - 空行布局
    - Markdown 链接格式
    - HTML 标签

4. 文件名必须保持一致。
5. 不要修改 `docs/zh-cn` 下的任何文件。
6. 不要擅自新增、删除、重排母版中不存在的内容。
7. 不要美化、改写、扩写原文含义，只做忠实翻译。
8. 保持原文的技术文档风格、语气、术语和表达习惯。
9. 若目标翻译文件已经存在，必须进行增量更新：
    - 保留仍然有效的已有译文。
    - 只更新与母版不一致、缺失或已变更的部分。
    - 不要无意义地整篇重译或重排。

10. 若目标翻译文件不存在，则基于母版完整创建。
11. 对于目标文档内已经存在且仍然准确的译文，不需要润色或重译；缺失内容应追加，过期、误译或误保留中文的内容应按母版增量修正。不得把正确的已有译文机械替换回中文。

## Markdown 与代码保护规则

是否需要翻译，应根据内容的实际含义和用途判断，不能仅根据反引号、代码字体或其他 Markdown 格式判断。反引号既可能表示技术字面量，也可能只是用于突出按钮名、菜单项或设置说明。

以下技术内容必须原样保留，不得翻译、改写或破坏：

- 文件路径，例如 `docs/zh-cn`
- 文件名，例如 `FUNCTIONS.md`
- 代码块中的程序代码、命令、配置及其技术字面量
- 行内代码中的技术标识或必须原样输入的值，例如 `rcRows`、`true`、`npm run build`
- 命令行内容
- 配置键名和实际存储的枚举值，例如 `player.speedButton`、`true`、`false`；不包括面向用户的设置名称或状态说明
- 函数名、类名、变量名、常量名
- API 名称
- URL
- Markdown 链接地址（同一文档的目标语言入口按下方链接规则处理）
- HTML 标签
- 版本号
- 语义化版本标记
- Issue / PR 编号
- commit hash
- 表格分隔符
- Front matter 字段名，如果存在

### 需要翻译的界面文案与自然语言

以下内容即使位于反引号内，也应翻译为目标语言，并保留原有反引号格式：

- 按钮名、菜单项、对话框选项，例如 `管理扩展程序`、`总是允许`。
- 设置项的显示名称，例如 `每行视频数量`、`翻译评论内容`。
- 面向用户的状态和默认值说明，例如 `开启`、`关闭`、`不可用`、`关闭；目标画质为 1080p`。
- 页面区域、提示语和操作说明，例如 `搜索结果中的Shorts视频`、`当前时间/长度`。

界面文案优先沿用仍然准确的已有译文；需要补译时，使用对应界面在目标语言中的名称。中文母版用于确定功能含义，不能因为母版使用中文，就把目标语言界面名称恢复成中文。无法确认界面名称时应说明疑点，不要将保留中文视为已经完成翻译。

示例：

| 中文母版 | 英文 | 日文 |
| --- | --- | --- |
| 点击 `管理扩展程序` | Click `Manage Extensions` | `拡張機能を管理` をクリックします |
| 点击 `总是允许` | Click `Always Allow` | `常に許可` をクリックします |
| 默认：`关闭；目标画质为 1080p` | Default: `Off; target quality 1080p` | デフォルト：`無効；目標画質は 1080p` |

同一片段混有自然语言和技术内容时，只翻译自然语言，保留标识、数值、单位和版本日期。例如 `rcRows 为 2` 可译为 `rcRows is 2`；`true` 作为配置值不能改成 `开启` 或 `On`，而作为界面状态说明的 `开启` 应正常翻译。

代码块也应区分用途：可执行代码、配置示例和命令按技术内容保护；仅用于排版的界面文字或操作说明应翻译其中的自然语言，并保留围栏、缩进和布局。不要仅凭代码块语言标签决定是否翻译。

### 链接保护

Markdown 链接中的显示文本可以按目标语言翻译。外部 URL、图片资源、下载地址等必须原样保留；指向项目文档的普通导航链接，如果目标语言已有对应文档，应使用该语言入口，并保留对应 anchor。不要把已有正确的本语言文档链接机械替换成中文母版链接。

例如 README 中的功能说明入口，英文使用 `/FUNCTIONS.md`，日文使用 `/docs/ja/FUNCTIONS.md`；更新日志入口同理。目标语言没有对应文档时，保留母版链接，不要编造路径。文档顶部的语言切换栏必须保留每种语言自己的名称和地址，不得将所有入口改为当前语言。

对于无需切换语言的地址，例如：

```md
[中文文本](../path/file.md)
```

可以翻译为：

```md
[English text](../path/file.md)
```

但括号内地址不得改变。

其中，切换不同语言的链接，括号内文字不要翻译，应当维持原样，例如

```md
[中文](/docs/zh-cn/FUNCTIONS.md) | [English](/FUNCTIONS.md) | [日本語](/docs/ja/FUNCTIONS.md)
```

不要翻译成

```md
[中国](/docs/zh-cn/FUNCTIONS.md) | [英語](/FUNCTIONS.md) | [日本語](/docs/ja/FUNCTIONS.md)
```

## FUNCTIONS.md、help/ios.md 特殊要求

`FUNCTIONS.md` / `help/ios.md` 中包含用于文档定位的 HTML anchor，例如：

```html
<a name="xxxx"></a>
```

此类内容必须逐字原样保留，包括：

- 标签名
- `name` 属性
- 属性值
- 引号
- 尖括号
- 标签位置

禁止翻译、删除、重命名或移动这些 anchor。

如果标题附近存在 anchor，翻译标题时也必须保持 anchor 与对应标题的相对位置不变。

## 翻译风格要求

### 英文 `en`

- 使用清晰、自然、准确的技术文档英文。
- 保持简洁，不要口语化。
- 技术术语优先使用行业通用表达。
- 不要为了流畅而改变原意。

### 日文 `ja`

- 使用自然、正式、准确的日文技术文档表达。
- 优先使用常见的软件开发文档术语。
- 保持语气克制、清晰。
- 不要过度意译。

## 更新流程

处理每个目标文件时，按以下流程执行：

1. 读取母版文件：
    - `docs/zh-cn/CHANGELOG.md`
    - `docs/zh-cn/FUNCTIONS.md`
    - `docs/zh-cn/help/ios.md`

2. 检查目标文件是否存在：
    - 不存在：创建完整翻译文件。
    - 已存在：对照母版结构进行增量更新。

3. 增量更新时：
    - 对比母版与目标文件的标题、段落、列表、表格、代码块、anchor 和链接结构。
    - 按含义区分受保护的技术字面量与需要翻译的界面文案、状态和自然语言说明，不能把所有反引号片段都列为禁止翻译。
    - 找出缺失、过期或与母版结构不一致的部分。
    - 仅翻译和更新这些部分。
    - 保留未变化部分的已有译文。
    - 修正格式偏差。

4. 写入目标文件。

5. 完成后进行自检。

## 自检清单

完成翻译后，必须确认：

- `docs/zh-cn` 未被修改。
- `/CHANGELOG.md` 已存在且内容完整。
- `/FUNCTIONS.md` 已存在且内容完整。
- `docs/en/help/ios.md` 已存在且内容完整。
- `docs/ja/CHANGELOG.md` 已存在且内容完整。
- `docs/ja/FUNCTIONS.md` 已存在且内容完整。
- `docs/ja/help/ios.md` 已存在且内容完整。
- 所有目标文件的 Markdown 结构与母版一致。
- 代码块和行内代码中的技术标识、命令、配置值、数值、单位及版本日期保持原样。
- 用反引号或代码块排版的按钮名、菜单项、设置显示名称、状态和自然语言说明已正确翻译，格式保持不变。
- 未将正确的已有译文替换回中文，未因反引号保护规则留下应翻译的中文。
- 自动校验应区分技术字面量与自然语言；禁止将所有反引号片段与母版逐字比较，并以通过检查为由把译文改回中文。

- 所有 `<a name="xxxx"></a>` anchor 在 `FUNCTIONS.md` 中完整保留。
- 文件名、目录名和路径正确。
- 已有目标文件是增量更新，而不是无意义整篇覆盖重译。
